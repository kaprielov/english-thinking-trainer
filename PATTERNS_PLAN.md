# Расширение базы паттернов

## Summary
Делаем не один список паттернов в коде, а конвейер: кандидаты из открытых корпусов -> нормализация -> ручная валидация -> публикация в приложении.

Для широкого покрытия я бы взял такой стек источников:
- [Tatoeba downloads](https://tatoeba.org/en/downloads) как источник открытых sentence pairs и примеров для learner-facing контента.
- [Tatoeba terms](https://tatoeba.org/en/terms_of_use) как опорную лицензионную базу: у текстовых предложений по умолчанию CC BY 2.0 FR, часть доступна под CC0.
- [OPUS](https://opus.nlpl.eu/) как большой агрегатор параллельных корпусов для поиска устойчивых конструкций и частотных шаблонов. Для него берем только выбранные открытые корпуса и проверяем лицензии на уровне конкретного корпуса.

## Key Changes
- Вынести паттерны из `src/data/patterns.ts` в отдельный контентный слой со схемой вроде `PatternSpec`.
- Добавить метаданные источника для каждого паттерна:
  - `sourceType` (`tatoeba`, `opus`, `manual`, `llm_candidate`)
  - `sourceId`
  - `license`
  - `confidence`
  - `reviewStatus`
- Сделать ingestion pipeline:
  - загрузка sentence pairs из Tatoeba;
  - загрузка кандидатов из выбранных OPUS-корпусов;
  - генерация candidate patterns по кластерам literal translation errors;
  - дедупликация и объединение близких формулировок;
  - экспорт в один JSON-файл, который читает приложение.
- Оставить LLM не источником истины, а только помощником:
  - группировка;
  - формулировка native thinking;
  - генерация common mistakes и упражнений;
  - финальная проверка человеком.
- Поддержать рост базы до 200-300 паттернов без раздувания бандла:
  - каталог данных отдельно от UI;
  - ленивое чтение/фильтрация;
  - mixed review строится уже из нормализованного каталога.

## Test Plan
- Проверить, что схема паттерна валидирует:
  - обязательные поля;
  - допустимые статусы;
  - непустые примеры и упражнения.
- Проверить ingestion на наборе тестовых источников:
  - Tatoeba pair;
  - OPUS pair;
  - вручную написанный паттерн;
  - LLM-кандидат.
- Проверить, что дубликаты сливаются корректно и не ломают exercises.
- Прогнать `npm run build` и убедиться, что приложение поднимается на расширенном каталоге.
- Вручную проверить 10-20 паттернов на качество:
  - естественность correct English;
  - адекватность native thinking;
  - отсутствие слишком буквальных/шумных примеров.

## Assumptions
- Источники только открытые и пригодные для повторного использования.
- Первый этап остается русско-английским.
- Автосбор не публикуется напрямую: он только генерирует кандидатов.
- Человек утверждает финальный паттерн перед публикацией.
- Сначала лучше взять качество и стабильный процесс, чем сразу гнаться за максимальным объемом.
